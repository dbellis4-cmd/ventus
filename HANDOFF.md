## Milestone 5 implementation

- Server-only Google OAuth with PKCE/state, `calendar.app.created` scope, a dedicated secondary Ventus calendar, encrypted refresh tokens, account-bound connection/link tables and service-only recovery RPCs. OAuth callback and same-origin authenticated Server Actions handle connect, status, sync and disconnect.
- Top-level task calendar preferences use category defaults and the existing “Add to Google Calendar” control. The Calendar sidebar link still opens Google Calendar in a new tab. Virtual and stored recurring occurrences export as standalone events for a rolling year. A Google deletion disables only its linked occurrence; other series dates remain linked. Ventus wins simultaneous mapped-field changes; unsupported Google event edits pause their link. Disconnect clears the token while leaving Google events.
- Synchronization runs on app open/manual request; successful task writes schedule an outbound pass after the response, and a once-daily route retries outbound work. Google edits are imported on app open/manual sync. Google event IDs, private metadata, stored mapping snapshots and a connection lease prevent duplicate writes and sync loops. Retry/backoff state and safe reauthorization status are stored locally. The official `@googleapis/calendar` and `google-auth-library` packages were added.
